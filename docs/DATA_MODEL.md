# Data model

Status: **partly implemented.** Tables marked *implemented* exist in `apps/server/src/db/schema.ts` with migrations in `apps/server/drizzle/`; the rest is the Phase 1 draft and is revised by the ticket that implements each table. Table names are plural `snake_case` (`accounts`, `sessions`, `audit_log`); the draft names below follow the same convention when implemented.

| Table       | Status                  |
| ----------- | ----------------------- |
| `accounts`  | implemented (ticket 1.1) |
| `sessions`  | implemented (ticket 1.1) |
| `audit_log` | implemented (ticket 1.1) |
| `characters` | implemented (ticket 1.3) |
| `item_instances` | implemented (tickets 1.6 / 1.7) |
| `activities` | implemented (ticket 1.6) |
| others      | draft                   |

## Principles
- **Content is code, state is data.** Classes, enemies, areas, item bases, affixes and loot tables are versioned definitions in `@worldforge/game-core`, referenced from the database by string id (`class_id = 'warrior'`). The database stores only player and world *state*.
- **Server-authoritative.** Every row below is written only by the server. Values derived from content (final stats, power score) are computed, not stored, unless needed for leaderboards.
- **Integers for value.** Gold and other currencies are `bigint`; no floats for anything that is spent or compared.
- **Auditability.** Value-changing operations write a ledger/audit row in the same transaction.
- IDs are UUIDv7 (`uuid`), generated by the server (`uuidv7()` in `src/db/uuid.ts`); timestamps `timestamptz` in UTC. Soft deletes only where noted.
- Value-changing writes go through `withTransaction()` and write their audit row with `writeAudit(tx, …)` in the same transaction.

## Entities

### accounts — implemented (1.1)
| Column          | Type        | Notes                                                        |
| --------------- | ----------- | ------------------------------------------------------------ |
| id              | uuid PK     | UUIDv7                                                       |
| email           | text        | stored trimmed as entered; unique on `lower(email)`          |
| display_name    | text        | unique on `lower(display_name)`                              |
| password_hash   | text        | argon2id PHC string (`$argon2id$v=19$m=19456,t=2,p=1$…`), written by 1.2 |
| character_slots | smallint    | default 2 (GDD §5.3), `CHECK (>= 0)`; per account, so slots can be granted later |
| active_character_id | uuid FK? | → `characters.id` `ON DELETE SET NULL`; the last selected character (ticket 1.3). Only ever set to one of the account's own characters (checked by the server) |
| created_at      | timestamptz | default `now()`                                              |
| updated_at      | timestamptz | default `now()`; set by the server on update                 |

Owner decision (GDD v0.3): real registration/login from Phase 1, no dev identity, so the draft's `auth_kind` column and separate `account_credential` table were dropped. If OAuth arrives later, it gets an `account_identities` table (provider, subject) and `password_hash` becomes nullable.

### sessions — implemented (1.1)
| Column     | Type        | Notes                                                             |
| ---------- | ----------- | ----------------------------------------------------------------- |
| id         | text PK     | SHA-256 hex of a random 256-bit token; the raw token only lives in the cookie |
| account_id | uuid FK     | → `accounts.id` `ON DELETE CASCADE`, indexed                      |
| created_at | timestamptz | default `now()`                                                   |
| expires_at | timestamptz | `CHECK (expires_at > created_at)`                                 |
| revoked_at | timestamptz | null while active; set on logout                                  |

A session is valid iff `revoked_at IS NULL AND expires_at > now()` (the server compares against its own clock). Login and registration insert a row (`created_at` = issue time, `expires_at` = + `SESSION_TTL_HOURS`); logout sets `revoked_at`. Pruning expired rows is left to a later maintenance job.

### characters — implemented (1.3)
| Column         | Type        | Notes                                            |
| -------------- | ----------- | ------------------------------------------------ |
| id             | uuid PK     | UUIDv7                                           |
| account_id     | uuid FK     | → `accounts.id` `ON DELETE CASCADE`, indexed. Count ≤ `accounts.character_slots`, enforced by the server under a `SELECT … FOR UPDATE` lock on the account row |
| name           | text        | trimmed as entered; unique on `lower(name)` across all accounts. Rules in game-core `validateCharacterName` (3–16 ASCII letters, one `'` or `-` between parts, a few reserved names) |
| class_id       | text        | game-core `ClassId`, validated by the server, immutable after creation. No DB `CHECK`, so adding a class needs no migration |
| appearance     | jsonb       | game-core `CharacterAppearance`: `{ banner }` (`ash`/`ember`/`moss`/`dusk`) |
| level          | integer     | default 1, `CHECK (>= 1)`                        |
| experience     | bigint      | default 0, `CHECK (>= 0)`; within the current level |
| gold           | bigint      | default 0, `CHECK (>= 0)`                        |
| farm_state     | jsonb?      | `{ seedSecret, cycleIndex, health, areaId? }` saved when the character's activity ends and restored when it starts again (ticket 1.9), so stop → start neither heals nor re-rolls. `areaId` (ticket 2.2) is the area of a cycle left unfinished by the stop; the next start replays that cycle there before travelling on. Never sent to clients |
| progress       | jsonb       | game-core `WorldProgress`, default `{"gravewardenDefeated": false}` (ticket 2.2). Unlock facts besides the level; written only by the server (the Gravewarden kill arrives with ticket 2.5) |
| version        | integer     | default 0; optimistic concurrency counter for later value-changing writes |
| created_at / updated_at | timestamptz | default `now()`                         |

`rng_state` from the draft is not used: settlement RNG comes from a per-character secret and cycle index (see `activities` and `farm_state`). Characters cannot be deleted or renamed yet.

### audit_log — implemented (1.1)
Append-only (the server never updates or deletes rows) for valuable or security-relevant events (auth events, item grants of epic+, deletions, rewards).
| Column       | Type        | Notes                                                                 |
| ------------ | ----------- | --------------------------------------------------------------------- |
| id           | uuid PK     | UUIDv7, so rows sort by time                                          |
| account_id   | uuid FK?    | → `accounts.id` `ON DELETE SET NULL` (anonymous events, e.g. failed login for an unknown email; history survives account deletion) |
| character_id | uuid FK?    | → `characters.id` `ON DELETE SET NULL` (added by ticket 1.3)          |
| event        | text        | dotted name, e.g. `account.register`, `auth.login`, `auth.login_failed` |
| data         | jsonb       | default `{}`; small, non-secret context (never passwords or tokens)   |
| created_at   | timestamptz | default `now()`                                                       |

Indexes: `(account_id, created_at)`, `(event, created_at)`.

### item_instances — implemented (shared by 1.6 / 1.7)
One owned item, created from a game-core `GeneratedItem`. Location is a column, not a separate table: `equipped_slot` null = in the inventory, otherwise equipped in that slot.
| Column        | Type        | Notes                                                              |
| ------------- | ----------- | ------------------------------------------------------------------ |
| id            | uuid PK     | UUIDv7                                                             |
| character_id  | uuid FK     | → `characters.id` `ON DELETE CASCADE`                              |
| base_id       | text        | game-core item base id                                             |
| rarity_id     | text        | game-core `RarityId`                                               |
| item_level    | integer     | check `>= 1`                                                       |
| affixes       | jsonb       | game-core `RolledAffix[]`, default `[]`                            |
| seed          | bigint      | generation seed (uint32), for audit and reproducibility            |
| equipped_slot | text?       | game-core `EquipmentSlotId`; unique per character when not null    |
| source        | text        | e.g. `farming`                                                     |
| created_at    | timestamptz | default `now()`                                                    |

Indexes: `(character_id)`; partial unique `(character_id, equipped_slot) where equipped_slot is not null`.

### activities — implemented (1.6)
The character's current farming activity. Settlement rules: `docs/FARMING.md`.
| Column         | Type        | Notes                                                              |
| -------------- | ----------- | ------------------------------------------------------------------ |
| character_id   | uuid PK/FK  | → `characters.id` `ON DELETE CASCADE`; one activity per character  |
| account_id     | uuid FK     | → `accounts.id` `ON DELETE CASCADE`; **unique** (one farming character per account) |
| area_id        | text        | game-core `AreaId` of the cycle in progress; the server checks `isAreaUnlocked` before setting it (ticket 2.2) |
| pending_area_id | text?      | area switch requested mid-cycle (ticket 2.2): the cycle in progress finishes in `area_id`, then the settlement moves the activity here. Null = none |
| seed_secret    | text        | 128-bit random hex, never sent to clients; carried over in `characters.farm_state` |
| settlement_seq | integer     | settlements that credited time, `CHECK (>= 0)` (audit only)         |
| cycle_index    | bigint      | cycles completed with `seed_secret`, `CHECK (>= 0)`; cycle `i` uses RNG `${seed_secret}:${i}` (ticket 1.9) |
| started_at     | timestamptz | start (or last area switch)                                        |
| settled_at     | timestamptz | progress computed up to here (server clock); indexed for the scheduler |
| last_seen_at   | timestamptz | last client contact; offline credit ends at `last_seen_at + OFFLINE_CAP_SECONDS` |
| carry_ms       | integer     | `unusedMs` carried into the next settlement, `CHECK (>= 0)`        |
| health         | integer?    | health between settlements; null = full                            |
| summary        | jsonb       | rewards since the client last collected the return summary         |
| updated_at     | timestamptz |                                                                    |

Stopping deletes the row after saving `seed_secret`, `cycle_index`, `health` (and the unfinished cycle's area) to `characters.farm_state` (the audit log keeps the history). Per-settlement history lives in the audit log (`activity.reward`) rather than an `offline_settlement` table for now.

### character_materials — implemented (2.3)
Materials a character holds. Granted only by settlement (later also the forge, 2.6).
| Column       | Type        | Notes                                                        |
| ------------ | ----------- | ------------------------------------------------------------ |
| character_id | uuid FK     | → `characters.id` `ON DELETE CASCADE`; PK with `material_id` |
| material_id  | text        | game-core `MaterialId`                                       |
| quantity     | bigint      | `CHECK (>= 0)`; stacks without a capacity limit for now      |
| updated_at   | timestamptz |                                                              |

Settlement adds with `INSERT … ON CONFLICT DO UPDATE SET quantity = quantity + excluded.quantity` in the settlement transaction (under the character lock).

### character_professions — implemented (2.3)
Gathering profession progress (game-core `ProfessionState`). A missing row means level 1 with 0 XP.
| Column        | Type        | Notes                                                          |
| ------------- | ----------- | -------------------------------------------------------------- |
| character_id  | uuid FK     | → `characters.id` `ON DELETE CASCADE`; PK with `profession_id` |
| profession_id | text        | game-core `ProfessionId`                                       |
| level         | integer     | `CHECK (>= 1)`; cap 50 in game-core config                     |
| experience    | bigint      | XP within the level, `CHECK (>= 0)`                            |
| updated_at    | timestamptz |                                                                |

Written by settlement only, read before `settleFarming` and written back in the same transaction.

### idempotency_key — not implemented (planned)
Phase 1 endpoints are idempotent by state (see `docs/API_CONVENTIONS.md`, Idempotency); this table arrives with the first non-idempotent value operation. `(account_id, key) PK`, `request_hash`, `response jsonb`, `status_code`, `created_at` (expired after 24h). See `docs/API_CONVENTIONS.md`.

## Relationships

```
account 1─* sessions
account 1─* character 1─1 activity
                     1─* item_instance (equipped_slot null = inventory)
                     1─* character_materials, 1─* character_professions
                     1─* currency_ledger
account 0..1─* audit_log
account 1─* idempotency_key
```
