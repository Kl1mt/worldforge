# Design system

The Worldforge UI language, set up in ticket 0.3. It covers GDD §3.2–§3.4. Pixel-art rules are in `ASSET_GUIDELINES.md`. Tokens live in `apps/web/src/styles/tokens.css`. Shared primitives (panels, meters, buttons, rarity classes) live in `apps/web/src/styles/base.css`.

The aim is a weathered artefact, not a dashboard. Iron, brass, dark wood and ledger paper set the tone. Corners are square, gradients appear only where light would actually fall, and glow is reserved for Legendary and Mythic items.

Screenshots of the prototype are in `docs/screenshots/phase-0/`. Regenerate them with `node tools/screenshots/phase-0.mjs` while `pnpm dev` is running. The login and register screens (ticket 1.2) are in `docs/screenshots/phase-1/` (`node tools/screenshots/auth.mjs`), and the character select and creation screens (ticket 1.3) next to them (`node tools/screenshots/characters.mjs`). The live game screens (ticket 1.8: area idle and farming, empty pack, comparison, after equip, character, return summary) come from the end-to-end run, `node tools/e2e/farm-loop.mjs` (see `docs/TECH_STACK.md`). The hub, world map and two areas (ticket 2.2) are in `docs/screenshots/phase-2/` (`node tools/screenshots/world.mjs` against the fast-clock e2e server). The Tavern and quest tracker (ticket 2.4) are next to them (`node tools/screenshots/tavern.mjs`, same servers). The first-session flow, the notices and the map list (ticket 2.7) are there too, from `node tools/e2e/first-session.mjs` (×600 clock, see `docs/TECH_STACK.md`). The report dialog, moderator queue and account standing (ticket 4.1) are in `docs/screenshots/phase-4/` (`node tools/screenshots/safety.mjs` against `E2E_SEED_MODERATOR=warden@graumark.test pnpm --filter @worldforge/server e2e:serve`).

## Colour tokens

Grounds and frames come from the palette sampled in `ASSET_GUIDELINES.md`, so the UI sits in the same light as the art.

| Group | Tokens | Use |
|---|---|---|
| Grounds | `--ink-950` … `--ink-750` | Page (`950`), sunken wells (`900`), surfaces (`850`). |
| Iron | `--iron-800` … `--iron-500` | Frame bands, rules, empty sockets. |
| Wood | `--wood-800` … `--wood-600` | Stash chest, character plaque. |
| Bone (text) | `--bone-100` … `--bone-400` | Primary text → faint captions. `100`–`300` pass WCAG AA on `--ink-850` (13.3, 9.2, 5.5:1). `--bone-400` (3.1:1) is only for non-essential captions. |
| Brass (primary accent) | `--brass-700` … `--brass-300` | Headings, active navigation, focus ring, crits, gold. |
| Crimson (secondary) | `--crimson-800` … `--crimson-400` | "Fighting" status, damage taken, error states. |
| Magic / nature | `--arcane-violet`, `--arcane-blue`, `--moss-*` | Affix text (blue), kills and nature (moss). |
| Meters | `--health`, `--rage` (+ `-back`) | Resource bars. Later classes add `--mana`, `--focus` and `--soul`. |
| Banners | `--banner-ash`, `--banner-ember`, `--banner-moss`, `--banner-dusk` | The character banner cosmetic, through `.banner-<id>` (sets `--banner`). Muted dyed-cloth tones that sit behind the art. |
| Deltas | `--delta-up`, `--delta-down` | Comparison gains and losses. Always shown with ▲/▼ and a hidden "Gain"/"Loss" label, never by colour alone. |

Semantic aliases (`--bg-page`, `--text`, `--text-dim`, `--accent`, `--line`, …) are what components use. Raw scale tokens are for the treatments below.

### Rarity

| Rarity | Token | Value |
|---|---|---|
| Common | `--rarity-common` | `#a7a198` |
| Uncommon | `--rarity-uncommon` | `#79a95a` |
| Rare | `--rarity-rare` | `#5292dc` |
| Epic | `--rarity-epic` | `#a46cd6` |
| Legendary | `--rarity-legendary` | `#e38b2f` |
| Mythic | `--rarity-mythic` | `#ec4a3c` |

All six pass WCAG AA as text on `--ink-850` (4.8:1 or better). Use them through the classes `.rarity-<id>`, which set `--rarity`. Components then read `var(--rarity)`. The rarity ids come from `game-core` (`RARITIES`).

**Void (ticket 3.5).** A variant, not a rarity, so it never takes a rarity colour or the rarity's place. Tokens `--void-light` (`#b9c3e0`, a cold voidlight, 10.3:1 on `--ink-850`) and `--void-rift` (`#07060d`). On the `ItemFrame` (`.item-frame--void`) it is the one treatment that touches the art: the icon is drained (`saturate(0.4)`) and edged with one art pixel of voidlight at 70 % (a hard pixel outline via `drop-shadow`, not a glow), it sits in a dark rift instead of the rarity wash, a voidlight hairline runs inside the rarity ring, and a hollow diamond ◇ marks the lower left corner. It keeps the rarity's border, notch and (Legendary/Mythic) outer glow, so a Void Legendary still reads Legendary first. In text: "Void" in voidlight before the rarity word in the tooltip, a "◇ Void" note with the bonus, the accessible label "…, Void legendary", and the drop moment ("A Void Legendary find", the item name prefixed "Void"). No new art, no animation.

Rarity is shown four ways: the frame border, a corner notch, the name colour, and the rarity word in the tooltip. Colour is never the only cue. Only Legendary and Mythic frames get a soft outer glow (GDD §3.2: effects for meaningful events). The Mythic red is deliberately brighter and warmer than the crimson accent, so a Mythic drop never reads as a UI error.

## Typography

| Role | Token | Face | Rules |
|---|---|---|---|
| Display | `--font-display` | IM Fell English SC (self-hosted via `@fontsource`) | Screen titles, section headings, the wordmark, nav labels, the crit number. Never body text, stats or numbers in tables. |
| Body / numeric | `--font-body` | Alegreya Sans 400/500/700 + italic | Everything else. `tabular-nums` is on globally, so stat columns line up. |

Scale: `--text-xs` 12, `sm` 14, `md` 16, `lg` 18, `xl` 22, `2xl` 28, `3xl` 36 px. Small caps labels use `.caps` (12 px, uppercase, `0.08em` tracking).

## Spacing, borders, radii

- Spacing is on a 4 px base: `--space-1` (4) … `--space-12` (48). The page gutter is `--gutter` (16 px), and the content max-width is `--content-max` (1320 px).
- Radius is `0`. Iron is never rounded. The two exceptions are intentional shapes, not rounded cards: the character niche's arch, and the chamfered tooltip corners (`clip-path`).
- Borders: `--border-hair` (iron-700), `--border-iron` (iron-600), `--border-brass`. Frames are built from layered `box-shadow` rings: a dark outline, an iron band, and an inner brass hairline (`--frame-iron`).

## Components

- **PixelSprite**: renders a manifest asset at an integer scale with `image-rendering: pixelated`. It floors fractional scales. If the image fails to load, it shows a dashed "art missing" box (the error state).
- **ItemFrame**: a 32 px icon socket (×1, ×2 or ×3). Its outer size is `socketSize(scale)` = 32 × scale + 8 px (`lib/pixel.ts`). It handles rarity frame, empty state (slot name), selected state, and keyboard/button semantics.
- **ItemTooltip**: name (the base name from game-core), rarity and slot, item level, an optional crimson note ("Warrior only"), implicit stats, affixes (blue), an optional comparison block with ▲/▼ deltas, and an optional action row on a rule at the foot (Equip / Discard / Unequip). Item display data and comparison math are in `apps/web/src/game/items.ts`: server items (base id, rarity, item level, rolled affixes) are joined with game-core content for names, icons and implicit stats. Unique effects and flavour text have no data yet and are not shown.
- **Meter**: health / rage / xp bars with `role="meter"`.
- **LabeledMeter**: a Meter with its name and value written above it ("Health 128 / 196", "Level 5 · 645 / 1,051 XP"). Used for the combatant HUD on the area scene (health + experience) and the character plaque (health). Health is the server's carried health (`activity.health`, full when null) over the derived maximum. Class resources (Rage …) exist only inside the combat simulation, so they have no meter on these screens. The visible text is `aria-hidden`; the meter keeps its accessible name and values.
- **Buttons**: `.btn`, an iron plate. The pressed state (`aria-pressed`) gets a brass underline. `.btn--brass` is a brass plate for the single primary action of a screen (the gate's submit, "Farm the fields", "Equip", the return dialog's "Back to the fields"); do not use it for secondary actions. Disabled buttons fade to 70 %.
- **Fields** (`.field`, in `gate.css`): a caps label, a sunken well with an iron rim (brass when focused, crimson when invalid), a faint hint, or an error line marked with ✕ plus text. Errors are tied to the input with `aria-describedby` and `aria-invalid`. Password wells have a Show/Hide toggle (`aria-pressed`).
- **Rule heading**: `.rule-heading`, display face with a brass rule that fades to the right.

## Pixel-art scaling in layouts

Ticket 0.4 raised every sprite on desktop by one integer step. Phone sizes (≤ 760 px, `PHONE_QUERY`) are the approved 0.3 sizes and do not change. Helpers and thresholds live in `apps/web/src/lib/pixel.ts`.

| Where | Phone (≤ 760 px) | Wider screens | Rule |
|---|---|---|---|
| Area backdrop | ×2, cropped around its centre | even N from `pixelScale(width, 384, { step: 2, min: 2, max: 4 })`, ×2 in the 768 px desktop column | Never shrunk. On phones the scene runs edge to edge. |
| Area hero and enemies | N/2 (×1) | **N (×2)** | `sceneSpriteScale`. Off-phone, sprites share the backdrop's pixel density. |
| Foes roster | ×1 | **×2** | Plinth grows to 140 × 136. |
| Recent spoils | ×1 | **×2** | Three per row. |
| Character portrait | ×2 / ×3 by niche width | **×4** in a 512 px niche when the doll has room | "Room" = `DOLL_LARGE_MIN_WIDTH` (936 px), the doll gets the `doll--large` class. Otherwise ×3. |
| Paper-doll sockets | ×2 | **×3** with the large doll | Slot text may wrap to two lines. |
| Inventory sockets | ×2, five per row | **×3, 8 × 5 grid** when the pack is ≥ `PACK_LARGE_MIN_WIDTH` (1270 px) | Otherwise ×2 in ten (or eight below 1260 px) columns. |
| Tooltips | ×2 | ×2 | Unchanged. |

The large character and inventory variants are chosen from the measured width of the doll and the pack body, not from the viewport, so they only switch on when the bigger art actually fits. At 1440 px both are on. At 1280 px the approved ×3 / ×2 layout is used.

## Layout and responsiveness

- Breakpoints: `760px` (phone: bottom navigation, single column, compact headings), `1080–1180px` (tablet: side columns drop below the main content).
- Navigation (ticket 2.2): Town (the hub, home; the Tavern, Forge and Merchant screens light it up), Map, Area (its hint is the current area's name), Character, Pack. A top bar on desktop. On phones, a fixed bottom bar with five 56 px tap targets (labels one size down), and the top bar keeps only the wordmark and gold. The wordmark leads to the hub.
- No horizontal page scroll down to 375 px. The screenshot script warns if it finds any.
- Screens: Hub = the town picture with hotspots (signpost list on phones) and a line saying where the hero is. Map = map board + ledger; choosing an open area starts or switches farming and goes to the Area screen; a deferred switch shows "Finishing the fight in …, then travelling to …" there and on the Area screen. Area = the current area (the fight in progress, else the last area farmed this visit, else the Abandoned Fields), built from game-core content for any area: title, levels, description, backdrop, foes and their frequency. Missing art falls back to a painted dusk backdrop and "?" silhouette plates for foes. Area = scene + Chronicle side column, with foes and spoils below. On desktop the Chronicle never sets the row height: it sizes to its entries and is capped at the height of the scene and the row below it, then scrolls. It never shows empty ruled rows. Every enemy has a small name plate with its level range (there are no per-hit events from the server, so the live health bars, target marker and hit number of the prototype are gone; ticket 1.8). On wide screens the plate spans the middle 62.5 % of the sprite so plates never touch. On phones names are 10 px. While the hero rests, the foes are dimmed. The header's pace strip (status, kills/min, drops this visit) sits beside the primary action: "Farm the fields" (brass) or "Call <hero> back" (iron); on phones the action runs full width under the strip. Character = three-column paper doll around the niche, with the attributes ledger and the inspected item beside it. On phones, the doll becomes a 4 × 3 socket grid under the portrait. Inventory = stash chest + pinned tooltips (selected with comparison, then currently equipped). Items are newest first. The chest draws at least 40 sockets (8 × 5) and adds rows as the pack fills up to the server's capacity (60, game-core `inventory.capacity`). On desktop with room, the chest is an 8 × 5 grid at ×3, about as tall as the tooltip column, so there is no empty floor under it. On phones, the grid has five sockets per row, shows four rows, and gives a free-slot count. The rarity filters sit on one horizontally scrollable row that runs to the screen edges (no visible scrollbar; the cut-off chip signals more).

## States

- **Loading / success / error:** the status bar's server line (`HealthLine`) shows "Reaching the server…", "Server online", or "Server offline: …" (`role="alert"`).
- **Session check:** while the client asks `GET /api/account`, the gate shows "Opening the gate / Checking your session…" (`role="status"`). If the server cannot be reached, it shows "The road is closed" with a Try again button. Forms show a busy label on submit ("Entering…", "Signing…"), a crimson-edged form alert (`role="alert"`) and per-field errors, and focus the first invalid field.
- **Characters:** after login the client loads `GET /api/characters` (the gate's "Checking your session…" stays up meanwhile; a failure shows "The muster roll is out of reach" with Try again). Without an active character every game route redirects to `#/characters`; with no characters at all that screen opens straight on creation ("Forge your first hero"). Creating shows "Forging…", per-field errors and a form alert. The shell's purse shows the real active character and links back to character select.
- **Game state (ticket 1.8):** `GameProvider` (`apps/web/src/game/`) loads the active character's activity and inventory, settles every 8 s while farming and the tab is visible, and builds the Chronicle from the settled summaries (kills + XP, gold, found items, deaths, level-ups, salvage and capped-time notes, all from the server). Loading: "Reading the field reports…" (area action), "Opening the pack…" (chest), "Tallying attributes…" (ledger). Errors: crimson-edged alert lines with Try again; a 401 sends the player back to the gate. Success: a moss-edged line after equip / unequip / discard ("Equipped Round Shield (Off-hand)."). Discard asks once more ("Discard for good?" / "Keep it").
- **Return summary:** on load, and when a tab returns after more than a minute hidden, the first settle's summary opens the "While you were away" dialog if at least a minute passed and something was credited or capped: time away, foes, XP, gold, items (icons + "and N more"), levels, deaths, salvage, and capped time in crimson. Escape or "Back to the fields" closes it; "Open the pack" goes to the inventory.
- **Empty:** a new hero's pack shows "Your pack is empty" with a link to the fields; Recent spoils says "Nothing found yet"; the Chronicle explains that it fills once the hero is out farming. Empty equipment sockets show the slot name. An inventory filter with no matches shows an explanation and a "Show all items" action. An empty Chronicle shows a quiet line. An unequipped selected slot shows a dashed hint.
- **Missing art:** `PixelSprite` fallback.
- **First session (ticket 2.7):** the waymarker guide walks create → farm → first drop → equip → Tavern. Steps are read from server state the client already holds (activity, inventory, route) and stored per account (`POST /api/account/guide`); the guide can be hidden at any time and comes back from the status bar's "Show first steps" until it is done. When all five are done it says "The road is yours." with a Close button. While the account is loading it is simply absent (no spinner).
- **"New" markers:** a brass "New" tab on item sockets (Pack, Recent spoils) and on Tavern notices (the story notice when it can be taken, untaken contract slips, quests ready to turn in), always as text. The nav shows the count ("Pack 3 new", "Town 2 new" for the Tavern; on phones a small "New" tab above the label). An item stops being new when inspected or when the player leaves the Pack; Tavern notices when the player leaves the Tavern. Kept per character in `localStorage` (a per-device convenience); the first look on a device counts as seen, except for a brand-new hero.
- **Unique boss drops:** the tooltip of a boss-exclusive base shows a brass "Unique boss drop" caps line and "Only The Gravewarden of The Nameless Crypt drops this." under the item level (the icons still borrow existing art until A-series art lands).

## Accessibility

- A visible focus ring everywhere: 2 px `--focus-ring` (brass-300), offset 2 px.
- A skip link. Focus moves to `<main>` after navigation.
- Interactive sockets are `<button>`s with `aria-pressed` and full labels (slot, item, rarity). Rarity filters are a labelled button group.
- `prefers-reduced-motion` disables transitions.

## Open points

- Each class shows its own portrait (`classPortrait(classId)`); the banner colour is the only visible cosmetic (GDD §5.1 asks for body, face, hair — later).

- The selected-socket outline and the focus ring are both brass. They are distinct (1 px vs 2 px, different tone), but this may need a stronger difference.
- Mana, Focus and Soul Fragments meter colours are not defined yet. They are needed once other classes are playable.
